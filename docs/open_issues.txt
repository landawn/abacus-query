Resolved issues from the deep source review (2026-09-24)

The five cases previously listed here are fixed and covered by regression tests
in the existing test classes. This list is not a claim that all SQL grammar
variants are supported.

1. JSON uniqueness clauses no longer hide real bindings.
   SELECT ARRAY[JSON_OBJECT('k' VALUE ? WITH UNIQUE KEYS)] reports one parameter.
   WITHOUT UNIQUE KEYS and mixed-style rejection are covered as well.
   Test: ParsedSqlTest.testParse_SqlJsonUniquenessClausesKeepRealBindings

2. Chained geometric casts follow the final type without phantom parameters.
   SELECT ?- CAST(? AS text)::line and SELECT ?- ?::text ::line each report one
   parameter. Intermediate type modifiers and multiword types are also covered.
   Test: ParsedSqlTest.testParse_ChainedGeometricCastsUseTheFinalType

3. Qualified adjacent geometric literals retain unary-operator recognition.
   SELECT ?-pg_catalog.line'(0,0),(1,0)' reports zero parameters and agrees with
   the equivalent form containing whitespace before the literal.
   Test: ParsedSqlTest.testParse_QualifiedAdjacentGeometricLiteralsMatchSpacedLiterals

4. Parenthesized JSON_ARRAY queries retain query scope.
   A parenthesized SELECT followed by UNION and nested JOIN predicates no longer
   mistakes NULL ON NULL across predicate boundaries for a constructor option.
   Real named bindings no longer cause a false mixed-style error in this case.
   Test: ParsedSqlTest.testParse_ParenthesizedJsonArrayQueryKeepsQueryScope

5. Unicode identifier mappings accept UESCAPE escape-string literals.
   U&"caf!00e9" UESCAPE E'!' retains table aliases, including in self-joins and
   nested mappings. Backslash, octal, hex and Unicode escapes are checked, while
   invalid escape clauses and expressions are not treated as bare identifiers.
   Tests: QueryUtilTest.testUnicodeEscapeStringClausesRetainTableAndNestedQualifiers
          QueryUtilTest.testUnicodeEscapeStringClausesDoNotHideOrInventQualifyingDots
          QueryUtilTest.testUnicodeEscapeStringsDoNotTreatInvalidClausesOrExpressionsAsIdentifiers
